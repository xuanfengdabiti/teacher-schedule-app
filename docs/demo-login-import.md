# 首次登录课表导入演示

本轮只演示“登录后按教师身份获取课表”的体验，使用本机虚构学校、账号和课程。没有连接真实学校网站、统一身份认证或教务接口。

## 画面与操作

1. 使用李老师、张老师或王老师登录。
2. 该账号当前学期首次在本机进入时，显示姓名、工号及“正在导入课表”，依次展示匹配教师信息、获取本学期课表、整理课程安排。
3. 成功后显示学期、实际授课课程数与课次数，点击“进入课表”完成。
4. 同一账号、同一连接地址、同一学期已有完成记录时，退出重登或恢复登录均直接进入课表。换账号或换学期分别处理。
5. 获取失败时可重试或返回登录，不显示导入成功、不写完成记录。

重复录制：在登录页展开“其他演示账号”，勾选“演示首次导入”，再选择老师并登录。本次只重新展示该账号的导入流程，不删除已有课程或教学记录；开关默认关闭。

画面保留短小的“演示模式 · 使用示例课表”说明。默认使用现有演示账号，不新增另一套认证系统。

## 数据实际来自哪里

演示环境启动脚本先将虚构模板和种子课程写入本机 Django/PostgreSQL。首次登录画面复用已有 `GET /api/v1/sync/bootstrap/` 读取这些数据，按 `is_mine=true` 且非取消课次统计本人课程，不把同教学班可见的其他老师课程计入。

本次不在登录时重新写入或生成课次，因此不会重复造课或覆盖备注、学时与交接。工号来自已登录账号的教师资料，用于呈现匹配过程；没有向外部学校提交账号或查询请求。

本地只保存按连接地址、账号和学期区分的小型完成记录；这不代表已经实现完整的离线课表存储。后续接到真实学校接口时，再替换数据读取入口。

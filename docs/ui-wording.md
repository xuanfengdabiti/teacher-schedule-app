# 教师界面措辞约定

本地演示面向老师。页面应直接说明课程、时间、地点和下一步操作，不把接口、同步或存储实现当作产品功能展示。实际检查记录见[本地演示验收](local-demo-acceptance.md)。

## 统一用词

| 场景 | 界面用词 | 不向老师展示 |
| --- | --- | --- |
| 编辑自己的教学备注 | 本次记录、保存草稿 | 服务器 v2、本地基于 v1 |
| 让同课老师看到备注 | 共享备注、已共享的备注 | 我的已发布版本、发布快照 |
| 查看其他老师的记录 | 同课老师的备注 | 同课教师已发布版本 |
| 把授课进度交给下一位老师 | 进度交接、交接给下次课 | 发交接、关联建议的下一课次 |
| 内容已被其他操作修改 | 内容已更新、保留当前输入、使用最新内容 | 服务器版本、基于版本重试、手动合并 |
| 已成功保存 | 已保存 | 已与服务端同步 |
| 教室记录及失物询问 | 教室与失物、教室记录、失物消息、回复 | 教室历史、协查收发、追加写入 |
| 排课信息不足 | 需确认、课表信息不全 | 覆盖完整、覆盖缺口等实现用语 |
| 授课时数记录 | 登记学时、已完成、剩余学时 | 服务端返回为准等处理过程 |
| 本地演示连接配置 | 连接设置、连接地址 | 普通课程页常驻 API 地址或服务信息 |

完整的排课数据表示信息齐全，不等于有人进行过人工核对。不要将其写成“已核对”。

## 保留真实操作的区别

- 保存草稿仅保存自己的编辑；共享备注才让同课老师看到。不能因改名而自动共享。
- 读取交接与确认交接是两个动作，分别显示已读、待确认或已确认。
- 调课候选保留可用、需确认、有冲突三类。申请提交后显示待审批，正式课表按审批结果更新。
- 备注、教学计划与完成学时是不同操作，保存备注不自动累计学时。
- 内容发生冲突时保留输入和现有备份机制，用一句话说明影响，按钮直接说明将保存哪份内容。

## 页面与提示规范

1. 标题和按钮用日常教学用语，整条流程保持一致，包含旧消息、弹窗、空状态和失败提示。
2. 不显示内部 UUID、对象代码、版本号、HTTP 状态或原始异常；课程名称、老师姓名、日期、房号及必要的工号正常保留。
3. 正常页面不堆放实现说明或重复提示。失败时说明当前问题和可进行的操作，保留具体可读的输入错误。
4. 新增或调整界面时同步检查实际操作后的消息、状态和旧记录，不能只改入口标题。
5. 内部字段、错误码、版本校验与同步规则保持原合同。此约定约束用户可见文案，不要求重命名接口和代码字段。

## 简短备注

老师可以只写一两句话，不要求三栏都填满。课表卡片中的“上次备注”最多显示两行，无备注不留占位；整周视图以小图标标记，保持课程和房号清楚。摘要不替代原备注全文，也不把保存草稿当作向其他老师共享。

# 教师课程表 App

面向研究生任课教师的移动教学辅助工具：今天上什么课、上一节讲到哪里、下次由谁接课、能调到哪个时段，都围绕同一份正式课表衔接。

**当前状态：后端已有教务数据模型（学校/学期/节次/校历例外、教师/学生、课程/开课/任课/选课、教室/占用、排课规则/课次/数据覆盖）、按规则生成课次的服务和 Admin 动作、只读课表读取接口（B13 后端：学期与校历、按半开日期区间查询本人/教学班/开课课次、课次详情、可见开课分页）、只读调课候选查询接口（B30）、调课申请/撤回、Admin 登记审批与正式生效（B31：提交与批准锁内再检查、SessionChange 前后快照、强制安排标识、统一事务写入口与幂等通知）、账号/JWT 后端切片（邮箱注册与验证、登录/刷新/退出、改密/重置、教师身份申报与 Admin 关联、`me`、停用；B01/B10 后端部分，使用 Mailpit 本地收信）、B14 后端部分（学校级 ChangeLog/同步游标、`sync/bootstrap/` 一致快照与 `sync/changes/` 增量接口、站内消息/设备/投递记录骨架和消息中心/设备接口）、B20 后端部分（三段私人草稿、显式发布快照、同 offering 的“上次记录”、base_version 冲突保留两份文本、`client_mutation_id` 事务幂等、同步 `notes`），B21 后端部分（交接预填、多接收人一接收人一条、显式已读/确认/撤回、备注发布版本快照、并发确认与撤回互斥、正式调课后向发送人发 `handoff_check` 核对提示），B22 后端部分（负责人维护专题计划与完整修订快照、专题分配不超课次学时、多教师课次只计一次、完成/更正/撤销留历史、服务端统一进度与过去待确认课次），B23 后端部分（可配置阈值与每日 `send_plan_reminders` 站内提醒、按 offering 当天去重），以及 B12a 数据导入：Admin 上传 CSV/XLSX、逐行校验与错误定位、预览统计、首次新建导入、完全相同内容的重复导入和 ImportIdentity 映射。** 导入更新/快照/人工决定项留待 B12b；尚无真实推送通道/投递命令/重试和移动 App（含 Flutter 离线草稿队列）。设备接口只保存绑定，不会向个推/APNs 发送，投递记录保持 `pending`，没有模拟发送成功；计划提醒目前也只落站内消息。头像、短信/微信/SSO 与限流也不在本次切片内。** 本期计划覆盖完整 Android/iOS App，教师网页版暂不开发。原始概要已归档，UI 图片为设计参考。

## 四个核心方向

1. **课表与智能调课**：今日/周/班级课表，检查授课教师、实际选课学生、教室冲突，申请并记录正式调整。
2. **教学备注与多教师交接**：已讲、未完成、下次计划，下次授课回顾与交接确认。
3. **教学计划与课时进度**：章节计划、完成确认、已完成与剩余学时、进度偏差提醒。
4. **教室历史与失物协查**：排定使用记录、自愿公开的联系方式、协查请求与回复。

完整版本同时包括注册登录、邮箱验证、密码找回、教师身份关联、数据导入、消息与推送、离线查课和个人设置。

## 默认实现路线

Flutter + Riverpod + Drift 构建移动端；Django 5.2 LTS + Django REST framework + PostgreSQL 提供服务；登录、密码流程、管理后台、XLSX 解析、通知等优先复用成熟组件。候选课表组件先验证再采用，只自写需要的教师业务和适配层。

预计一个有相关经验的全职开发者约 9–12 周完成首版，外部账号开通、学校数据与商店审核时间另计。阶段目标见详细方案，不以静态页面代替功能完成。

## 数据与许可证

[模板目录](templates/import/README.md)中的姓名、邮箱、学号和课表全部为虚构示例。真实学校导出文件、账号参数和签名材料不放进公开仓库。

本项目当前尚未声明源代码开源许可证；公开仓库不等于已授予 MIT 等再分发许可。后续实际引入第三方源码时保留其原有许可与归属，详见第三方复用记录。
